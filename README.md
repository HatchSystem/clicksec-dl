## セットアップ

Python 3.12 以上と [uv](https://docs.astral.sh/uv/) が必要です。

```sh
uv sync
cp .env.example .env   # ログイン ID / パスワードを記入
```

## 使い方

初回は銘柄カタログを作ります。サイトの一覧ページを年ごとに走査し、銘柄 ID・コード・取得できる月を `catalog/{fx|cfd}.json` に保存します（FX は約 20 ページ、1 秒間隔）。リポジトリには作成済みのカタログ（FX は 2007 年以降の 44 件、CFD は 2011 年以降の 38 件。取り扱い終了銘柄を含む。2026-10 時点）が含まれています。

```sh
uv run clicksec-dl catalog update fx
uv run clicksec-dl catalog update cfd --years 2024-2026   # 年を絞る場合
```

ダウンロード時は、対象期間の年の一覧ページを自動で再走査してカタログを更新し、一覧にリンクがある月だけを要求します。新しく追加された銘柄・月はこれで取り込まれます。サイトから消えた銘柄もカタログには残るため、過去の月を指定して取得できます。

```sh
# FXネオ: 2024-12〜2025-01 の USDJPY と EURJPY を data/ 以下へ保存
uv run clicksec-dl fx --from 2024-12 --to 2025-01 --symbols USDJPY EURJPY

# CFD: 2025-01 の全銘柄。ZIP の中身も展開する
uv run clicksec-dl cfd --from 2025-01 --extract

# 当月 / 前月 / 前月〜当月（月は日本時間で判定）
uv run clicksec-dl fx --this-month
uv run clicksec-dl fx --last-month
uv run clicksec-dl fx --last-month --this-month

# カタログの銘柄一覧（ID、取得できる期間、表示名）
uv run clicksec-dl symbols fx

# ログインせずに対象だけ確認（保存済みカタログを使う）
uv run clicksec-dl fx --from 2024-12 --dry-run
```

同じ銘柄コードでも時期によって ID が異なることがあります（例: FX の USDJPY は 2016-02 までが ID `01`、2016-01 以降が `21`）。年月ごとにカタログから正しい ID を選ぶので、利用者はコードだけを指定します。

保存先は `data/{fx|cfd}/{銘柄コード}/{サーバーが返すファイル名}` です。同名ファイルが既にあれば取得をスキップし、`--force` で上書きします。

ただし、その月が終わる前（翌月 2 日 0:00 JST より前）に保存したファイルは、月の途中までのデータしか含まない途中版とみなし、`--force` が無くても取り直して上書きします。`--extract` を付けている場合は、展開済みの CSV も新しい内容で上書きします。当月分を毎日取り直したり、月内に取得した前月分を月明けに最新化したりする場合も、同じコマンドを実行するだけで済みます。

| オプション | 既定 | 説明 |
|---|---|---|
| `--from` / `--to` | - / `--from` と同じ | 対象期間（YYYY-MM、両端含む） |
| `--this-month` | off | 当月（日本時間）。`--last-month` と併用すると前月〜当月 |
| `--last-month` | off | 前月（日本時間） |
| `--symbols` | カタログの全銘柄 | 銘柄コード |
| `--out` | `data` | 保存先ルート |
| `--force` | off | 既存ファイルを再取得して上書き |
| `--extract` | off | ZIP の中身を同じディレクトリへ展開 |
| `--dry-run` | off | ログインせず、保存済みカタログで対象だけ表示 |
| `--no-scan` | off | 一覧ページを再走査せず、保存済みカタログだけで対象を決める |
| `--catalog-dir` | `catalog` | カタログの保存先 |
| `--interval` | FX 1 秒 / CFD 2 秒 | リクエスト間の待機 |
| `--retries` | 3 | 1 件あたりの最大試行回数 |
| `--timeout` | 60 秒 | HTTP のタイムアウト |
| `--env-file` | `.env` | 認証情報を読むファイル |

期間は `--from` か、`--this-month` / `--last-month` のどちらかで必ず指定します。両方の形式は同時に指定できません。

終了コード: `0` 全件成功、`1` 失敗した件がある、`2` 引数・認証情報・ログインのエラー。

## 所要時間と高速化

時間の大部分は、要求の間に空ける待機（`--interval`）です。1 件あたりの通信と保存は、回線の状態にもよりますが 0.2〜0.5 秒程度です。

2025 年 1 年分（FX 30 銘柄 352 件・142 MB、CFD 36 銘柄 384 件・125 MB）の実測値（2026-10）:

| 実行方法 | 所要時間 |
|---|---|
| 既定の待機（FX 1 秒 / CFD 2 秒）で FX → CFD の順に実行 | 約 20 分（1 件あたり FX 約 1.2 秒、CFD 約 2.2 秒からの見積もり） |
| `--interval 0` で FX と CFD を同時に実行 | 約 1.5〜3 分（回線の状態による） |

FX と CFD は別のプロセスとして同時に実行できます。ログインは各プロセスで 1 回ずつで、互いのセッションには影響しません。

```sh
# bash の例: FX と CFD を待機なしで同時に取得する
uv run clicksec-dl fx  --from 2025-01 --to 2025-12 --interval 0 &
uv run clicksec-dl cfd --from 2025-01 --to 2025-12 --interval 0 &
wait
```

> [!WARNING]
> 待機を短くするほど、短時間に大量のアクセスを行うことになり、アクセス制限や口座への措置を受ける可能性が高まります。同じ商品をさらに複数のプロセスへ分けると同じ口座で何度もログインすることになるため、推奨しません。

### 失敗したときの再実行

- 通信エラーは 1 件ごとに最大 `--retries` 回まで再試行し、それでも失敗した件を「失敗」として集計します（終了コード `1`）。
- 同じコマンドをもう一度実行すれば、保存済みの完全なファイルはスキップされ、失敗した件や途中版だけを取り直します。
- 1 回の実行でログインするのは最初の 1 回だけです。途中でセッションが切れても自動では再ログインしないため、その後の件は失敗になります。再実行してください。
- 回線が切れている間は、1 件ごとにタイムアウト（`--timeout`、既定 60 秒）まで待ってから再試行するため、全体の所要時間が大きく延びます。

## 環境変数

| 変数 | 必須 | 用途 |
|---|---|---|
| `CLICKSEC_J_USERNAME` | 必須 | ログイン ID |
| `CLICKSEC_J_PASSWORD` | 必須 | ログインパスワード |
| `CLICKSEC_USER_AGENT` | 任意 | 送信する User-Agent の上書き |

パスワードをコマンドライン引数で渡すオプションは、シェル履歴に残るため用意していません。CFD の要求に必要な口座の `guid` は、ログイン応答から自動で取得します。

## 仕組み

- ログインは同社 SSO のログインフォームへ ID とパスワードを送ります。CFD の要求に必要な口座の `guid` はログイン応答から取り出します。Cookie、トークン、`guid` はログへ出しません。
- 一覧ページ（`historicalDataList.do`）は、年ごとに「銘柄 × 月」のダウンロードリンクを並べています。リンクがある月だけを要求します。
- 同じコードでも時期によって ID が異なる銘柄や、複数の銘柄で ID を共有する例（CFD の `Copper_Futures` と `Iron_Ore_Futures`）があるため、カタログは ID とコードの組で管理します。
- ブラウザ相当のヘッダーを送り、要求の間に既定で FX 1 秒、CFD 2 秒の間隔を空けます。
